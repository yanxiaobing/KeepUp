# 计步估算热量

更新：2026-09-22，补齐 F10 的计步热量展示。

## 口径与实现

- 原版依据：`PunchCard/Cards/WalkCard/PCWalkCardService.m:117/202` 将步数乘以 `0.03f` 写入整数热量字段。KeepUp 使用固定的每步 0.03 大卡，向下取整；整数运算 `steps * 3 / 100` 避免浮点误差造成整值边界少一大卡。
- `ActivityEnergy.stepCalories` 为唯一计算入口，校验 0～1,000,000 整数步数。未知、负数、超范围和非整数记录不产生热量；真实零步为 0。6,500 步显示 195 大卡。
- 计步详情、卡片预览、详情/卡片导出复用热量组件；中英文均标为“估算”，并解释固定系数。不是系统测量，也不使用体重、距离或分时完整性推算。
- 时间线原有当日预计消耗汇总通过同一入口纳入已保存计步打卡，不重复叠加 `step_records`。未达标且尚无打卡的测量只在计步页展示，沿用当日汇总仅统计打卡记录的范围。
- 历史数据直接从保存的步数计算，无需数据库迁移；当前体重和目标调整不影响固定系数。日总步数被有效新读数修正时，热量随同一个总量更新。
- 普通卡配置、跑步/骑行记录的运动热量算法保持原有逻辑。

## 验证

iPhone 17 Pro / iOS 26.5 模拟器通过 168 项 Swift Testing、9 项提醒 XCTest、7 项计步 UI 回归。覆盖固定系数和取整边界、零步/未知/非法值、历史记录与详情口径一致，以及中英文分享、时间线汇总和拒权缓存。

已检查中英文完整导出 PNG 与中文零步页面，热量及解释无截断。637 条双语文案、预置配置和 diff 空白检查通过。首轮新增测试尝试修改不可变的记录字段导致编译失败，改为构造独立样例后重跑全部通过，业务模型保持不可变。

结果在 `.build/StepsEnergyFinal.xcresult`、`.build/steps-energy-final-tests.log`，截图在 `.build/steps-energy-review`。真实传感器验收继续后置。

# 计步、本地化与提醒完善

日期：2026-09-20。主代理统一接入工程与数据层，三个子代理分别实现计步模块、本地化清理、提醒完善，并交叉审查存储与入口。

## 计步

- `Features/Steps` 使用 Core Motion，首次读取由用户点击授权；不支持、未授权、拒绝、读取失败均有明确状态，不把失败当成零步。
- 计步目录入口、首页未达标固定卡、计步已完成卡详情、时间线与个人页目标入口已接通。
- 沿用 PunchCard 的 5000～30000 步（每档1000）目标轮盘，第一次设置当天生效，后续修改次日生效；使用 Defaults 保存按日生效的目标历史。
- 复用原版步行男女插画，保留青绿渐变、白色进度圆环与目标页布局；显示真实步数和可用的步行距离，不编造卡路里或活跃时长。
- 打开 App 后，对已设目标且已授权的用户启动前台监测；读取最近7个日历日，并在返回前台、跨日或时区变化时更新。不承诺 App 未运行时自动处理传感器或立即生成打卡记录。
- 两个传感器对象分别负责查询与持续更新，旧查询会话通过 generation 失效；落库依据测量区间结束时间，而非回调到达时间。
- DEBUG 下显式 `-ui-testing -ui-testing-steps` 才可注入模拟源，发布版本不包含测试源。

## 持久化与目标语义

WCDB schema 升至7，新增 `step_records`，使用日历日字符串作为主键。保留既有数据库路径、表和内容，schema 6 升级测试验证原记录不变。

- `StepRecord` 保存日测量值、时区、距离、测量时间与该日目标快照；测量和完成记录分开。
- 只有达到目标才产生 `steps.YYYY-MM-DD` 唯一打卡记录，并在同一事务内完成当天待办；零步与未达标测量不增加打卡次数或连续天数。
- 后续读数更新同一条记录，保留备注、照片和初始录入时间；更旧测量不覆盖新值。
- 当天已达标后，传感器下调读数不自动撤销已获得的打卡。用户主动删除则在同一事务标记该日 `checkInDeleted`，之后仍更新测量，但不重建当天打卡；翌日独立。
- 通用手工录入接口拒绝计步卡，避免绕过传感器和目标规则。

## 本地化

- 固定品牌、标点、英文插画覆盖文字采用 `verbatim`，避免错误提取。
- 5处整数插值明确使用 `%lld` 模板；详情标题与 BMI 模板补齐双语。
- 不按 `stale` 标记批量清理：运行时 `localized()` 与 JSON 引用的词条仍需保留。
- 校验脚本检查格式参数的位置、类型、数量和更多直接调用；新增计步与提醒双语文案。

## 提醒

- 按稳定 identifier 差量同步，仅删除过期、不再需要的请求；未变请求保留，时间或语言变更替换原请求。
- 替换失败保留旧提醒，初次写入失败会在后续同步重试；维持前缀隔离、容量预算与最新快照优先。
- 系统通知对象封装在适配器内；跨 actor 只传 Sendable 值描述，测试可注入通知中心与时钟。
- 提醒编辑页与列表显示系统权限关闭提示，提供系统设置入口，回前台刷新权限。
- 继续采用现有有限通知队列。长期不打开 App 后队列耗尽的问题未在本轮改成后台永久补充，不能当作已解决。

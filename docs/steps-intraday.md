# 计步日内详情

更新：2026-09-22，补齐 F10/F15 的分时步数、小时图和活跃时长。

## 数据口径

原版 `PCHealthDataService.requestHourStepCountSetByDate` 每五分钟查询 Core Motion；`BCWalkTimeSlotService.getWalkActiveTimeWithWalkCard` 累加超过 5 步的区间时长。本次沿用该阈值，界面明确标为“估算活跃时长”，并解释这不是精确运动时长。末尾不足五分钟的区间只累加实际查询时长。零步显示 0 分钟；有任何区间缺测时不生成完整活跃时长。

原版 `PCWalkCardService` 使用步数乘 0.03 的固定热量估算，并非系统测量。此次不新增该热量显示，继续保持此前不编造计步热量的口径。

参考 [Apple CMPedometer](https://developer.apple.com/documentation/coremotion/cmpedometer)：对指定起止时间查询历史数据，分时值不由日总步数均摊生成。

## 实现

- 只有计步详情页请求分时数据，首页监测和首次授权仍只查询日总量。与总量/实时更新分开执行异步串行查询，不阻塞主线程。
- 每五分钟一段，包含真实零值；查询错误保留 nil。小时有缺失区间时不画成零步，显示数据不完整提示和重试入口。当天图表覆盖整天，未来时段不补零；标明分时数据截止时间。
- 当天页面定期检查，分时数据超过五分钟后刷新；离开页面、后台和跨日刷新通过取消及 generation 丢弃过期结果。对一小时前已成功查询的完整区间使用当前数据源实例内缓存，近期区间重新查询以允许修正。
- 日界线、小时分组和展示使用记录时区；测试覆盖夏令时的 23/25 小时日，重复小时按绝对时间区分。
- `StepRecord` JSON 增加可选 `intraday`，无需修改数据库表。旧记录没有分时数据仍展示日总量并提示缺测。记录可在系统七天读取窗口外或拒权时继续展示已保存分时数据。
- 日总量更新保留同一时区的分时数据；晚到的分时结果只补充更近的详情，不回退总步数、不重复创建打卡。保存前检查区间顺序、边界、数量、步数和截止时间。
- 详情样式分享复用同一个图表和估算时长组件；卡片样式保留原有简洁布局。中英文文案已补齐。

## 验证

- iPhone 17 Pro / iOS 26.5 模拟器通过 167 项 Swift Testing、9 项提醒 XCTest，以及 7 项计步 UI 回归。覆盖旧数据、23/25 小时日、缺测/零步、晚到详情不覆盖新总量、重开数据库、后台队列回调和取消查询。
- 7 项 UI 回归包含中英文详情/卡片分享、目标与唯一打卡、拒权缓存、未达标入口、不支持设备，以及新增的分时缺测/零步。原有两项用例因首页已改为页面导航而失败，改为系统返回操作后全部通过，保留原业务断言。
- 截图检查发现 Swift Charts 默认柱宽和标记方向不符合预期，改为显式小时范围和从零开始的矩形柱，并复跑相关 UI 与图片渲染验证。
- 中英文 634 条文案、预置配置和 `git diff --check` 通过。
- 日志及结果位于 `.build/steps-intraday-*-tests.log`、`.build/StepsIntradayFinal.xcresult`、`.build/StepsIntradayChart.xcresult` 和图表/海报专项结果；截图在 `.build/steps-intraday-*-review`。

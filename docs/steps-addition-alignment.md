# 计步卡添加与首页流程对齐

日期：2026-09-24。

## 原因与原版依据

之前目录选择计步卡只进入 `StepsView`，必须再打开右上角设置并保存目标才能固定到首页。入口没有说明这一步，表现为“不能添加”。

对照 PunchCard `PCPunchCardService.punchWalkCardWithCard`、`BCWalkCardTargetView`、`PCStepTargetViewController`、`PCWalkCardService` 和 `XBCalendarWalkCell`：添加计步卡需要保存每日目标并固定卡片，达到目标自动打卡，首页显示实际步数与圆环进度。

## 本次修改

- 推荐目录增加计步卡快捷入口，生活分类和搜索入口复用同一流程。
- 未启用时直接打开目标设置；保存后关闭目录返回今天的首页，取消不创建卡片。已有计步卡进入详情，避免重复添加。
- 计步卡使用自身添加流程，不落入未来日期的普通待办编辑器。
- 第一次设置当天生效，修改次日生效；保存未修改的值不新增目标历史。
- 首页计步卡使用步数圆环，未获得数据时显示未知状态，未达标显示实际进度，达标后仍按每日唯一记录持久化。
- 移除固定卡时停止首页监测；数据保存入口也检查启用状态，阻止后续回调继续保存。重新添加恢复监测，保留已有历史。
- 最近七天的行可打开对应日期详情，复用分时统计、热量、目标与分享展示。

## 保留的数据规则

不允许手工伪造步数。未达标的测量与成功打卡分开；传感器失败不写假零；权限拒绝时可查看已有缓存。主动删除当天成功记录后，不因传感器再次回调恢复当天打卡。首次添加使用现有目标设置页，未复制原版 UIKit 浮层代码。

## 验证范围

新增 UI 覆盖添加、取消、返回首页、重启、移除、重新添加及历史详情。新增业务回归验证停用卡片不再保存、重新启用恢复保存，以及未修改目标不增加生效日期。现有计步测试覆盖达标唯一记录、权限拒绝缓存、设备不支持、分时统计和中英文分享。

真机传感器、锁屏和后台行为按项目约定留待统一验收。

# 骑行与室内跑步功能对齐

2026-09-20，延续户外跑步实现，按用户要求优先补齐可操作功能。真机检查后置，不阻塞后续运动设置和详情功能。

## 本轮实现

- 准备页按原版提供户外跑步、室内跑步、骑行三种模式；骑行卡默认选中骑行。首页待打卡、今日计划、返回未完成运动、历史详情均接入。
- 三种模式共用一个活动会话；从别的卡片入口打开时仍返回当前运动，不能修改已开始会话的类型。
- 骑行使用 GPS，按原版采用至少 500 米的保存门槛、独立速度过滤上限，显示平均速度及完整公里分段速度（公里/小时）。骑行记录属于 `punchcard.96`，完成时只消费骑行计划。
- 室内跑步使用 CMPedometer 的累计距离和累计步数，不请求 GPS、不显示地图；准备页复用原版室内插图。运动权限未授予、被拒绝或设备不支持距离测量有独立状态，不用固定步长伪造距离。
- 室内跑步保留暂停、继续、结束、丢弃、重启恢复、失败重试；每段订阅独立，按累计差分避免重复计算，暂停和进程退出期间不补入数据。至少 100 米可保存，显示有效时长、距离、配速、步数、平均步频和完整公里分段。
- 三种模式继续使用统一 WCDB 表注册、JSON 编解码与原子完成事务；室内属于 `punchcard.2`，完成只消费跑步计划。已结束和已删除记录不被迟到检查点复活。

## 数据兼容

`RunningSession` 增加模式和室内步数；旧 JSON 缺少字段时分别按户外跑步、0 步解码。schema 升为 9：表结构不需要重建，但阻止旧版 App 忽略模式字段后错误改写骑行数据。旧跑步草稿/记录保留，新增类型必须与同 ID 的持久化会话一致。

室内记录不能携带 GPS 点，户外/骑行不将室内步数混入。保留已有自然日、时区、revision、事务和删除标记规则。旧手工跑步、骑行记录没有轨迹时仍回退普通详情。

## 验证范围

单元与存储测试覆盖模式默认值和旧 JSON、schema 8 升级、三模式卡片归属/计划清理、100/500 米边界、模式不可变、室内累计差分、暂停恢复和旧订阅隔离。UI 使用显式 DEBUG fixture，覆盖室内准备/保存/跨入口回到同一会话、运动拒权、骑行速度与历史，并回归已有户外流程。

2026-09-20：80 项 Swift Testing、9 项提醒 XCTest、6 项运动 UI 测试通过。骑行入口默认模式问题已通过 item 驱动传参修复，随后复跑骑行与室内跨入口测试通过。520 条中英文文案、772 份资源哈希与配置检查通过。室内插图保留原资源，气泡通过 SwiftUI 本地化展示，英文界面不再显示烘焙中文。

这些检查验证功能与数据行为，不声称已经测得实际传感器精度。

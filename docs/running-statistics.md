# 运动统计汇总

更新：2026-09-20，对应 F17 的三种运动汇总部分。

## 原版依据与本批边界

对照 `PunchCard/Me/PCMeService.m:114` 的 `getCardDataList`，其中累计小时等写死为 `10086`，全仓库未找到调用；`PCMeViewController.m:137` 起的列表只显示三组设置。`Cards/RunCard/Services/BCRunService.m:204/224` 的累计跑步、骑行公里方法确实从运动结果求和，但同样未找到调用方。因此不能宣称原版已有可达的完整月统计页面，也不能把占位值复制到 KeepUp。

本批按已确认的执行清单补齐真实运动汇总，在“我的”提供独立入口。这是 KeepUp 新增的可达统计入口，不是对不存在的原版页面做 1:1 复刻。普通打卡、步行的完整统计以及全 App 逐页交互验收不因此被标记完成。

## 已实现口径

- 仅统计已保存、带明确运动模式的记录：户外跑步、室内跑步、骑行。进行中的草稿、丢弃会话、没有模式的旧手工公里记录不混入统计，界面说明范围。
- 支持全部模式/单模式、全部时间/月份筛选，月份来自所有运动记录；日期依据保存时的 `LocalDay`，切换时区不改变归属年月。
- 展示次数、去重天数、总公里、有效时间、已知热量、最长距离；单模式显示按总距离与总有效时间计算的平均配速或速度，不平均各条配速。全部模式混合时不显示统一配速。
- 热量逐条按详情同样规则四舍五入，再累加，保持与时间线一致；不读取当前体重重新估算历史热量。
- 缺少历史时长或热量时明确说明不完整，只累计已有值；全部缺失显示“—”，真实 0 与缺失区分。时长不完整时平均速度和配速不显示。
- 按日列出记录，进入已有详情可编辑附加内容或删除；从同一 `AppModel.snapshot` 重新计算，删除后列表、总计和月份同步更新。

## WCDB schema 11

entries 增加可空 `runningElapsedSeconds`。新运动结束事务把有效时间与模式、距离、热量一起写入轻量摘要；普通快照和统计不读取所有历史轨迹。

旧库升级时逐条读取已完成会话回填时长，不同时把全部轨迹留在内存。schema 10 的历史热量原样保留，不重算；schema 9 及更旧的模式/热量迁移继续执行。找不到会话的摘要保留时长未知，手工记录保持无模式。数据库版本更新与字段回填在同一事务内，失败时不标记升级成功。

## 验证

通过 134 项 Swift Testing、9 项通知 XCTest 和 5 项运动统计/详情 UI 回归，共 148 项。覆盖 schema 9/10 升级、历史热量冻结、时长缺失、跨年月份与记录日、三模式筛选、加权平均、重复保存、删除后重启、详情编辑及分享回归；核对全部时间、单模式月份和删除后空状态截图。605 条中英文文案和原始配置校验通过。首轮测试对 GPS 距离使用精确浮点相等而失败，改为厘米级误差断言后重跑单元测试通过，业务计算未变更。

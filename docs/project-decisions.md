# 项目决策与范围

更新日期：2026-09-20。信息来源：本项目讨论与用户明确选择。

## 已确认

| 项目 | 决定 |
| --- | --- |
| 产品名称 | KeepUp |
| 平台与最低系统 | 仅 iOS，最低 iOS 26.0 |
| 首发设备 | iPhone；不制作 iPad 专属布局 |
| Bundle ID | `com.bestlife.keepup` |
| 功能范围 | 与 PunchCard 一致，暂不增加功能 |
| 界面方向 | 复用 PunchCard 的 UI、布局、交互和图片资源；适配 iOS 26 与中英文，不另做视觉设计 |
| 系统体验 | 结合最低 iOS 26.0 逐项判断：业务页面设计与资源按原版还原，系统控件及第三方组件可采用 iOS 26 原生体验，包括玻璃样式；避免仅为旧外观锁定旧 SDK |
| 代码策略 | 独立工程与数据；实现可重写，但“不强调代码复用”不代表允许重新设计 UI |
| 数据与会员 | 完全独立，不导入旧数据，不共享会员权益 |
| 全球化 | 英文、简体中文；同时处理地区、日期、时区、单位与布局 |

| 项目 | 建议 | 状态 |
| --- | --- | --- |
| 客户端 | Swift、Swift 6 语言模式、SwiftUI、Observation | 已在正式工程落地 |
| 架构 | 按功能模块组织，页面状态、业务服务、数据访问分层 | 建议；保持轻量，不强制所有页面配 ViewModel |

| 包管理 | SPM，固定直接依赖版本并保留解析结果 | 正式工程固定 WCDB 2.1.16、TOCropViewController 3.2.0，保留 Package.resolved |

| 计步 | 实时性与授权体验优先；CM 暂优先，HealthKit 待真机对比 | 用户允许在满足实时体验时改用 HealthKit，不受旧代码约束 |

## 当前开发范围

用户最新确认：前期直接使用 WCDB 保存数据，先完成本地功能与中英文界面。CloudKit 不作为开工条件，也不要求现在提供开发者 Team 或云容器。

用户于 2026-09-20 明确调整优先级：先完成与 PunchCard 的功能对齐，真机传感器、后台定位和地图对齐验收集中后置。继续进行必要的单元测试、模拟器交互验证和原版源码核对，不能因为缺少真机结果而停下后续功能开发。

## 独立资源约定

- CloudKit 容器候选名称：`iCloud.com.bestlife.keepup`。这是建议值，尚未在开发者后台创建或验证授权。
- 自己的 Keychain 命名空间；不继承原项目共享 Keychain access group。
- 自己的内购产品、广告 App ID / 广告位、统计项目与远程配置路径。
- 不复制旧项目密钥、生产配置、收据验证秘密或用户数据。
- 已按用户要求配置 App Group `group.com.bestlife.keepup`；目前数据库与偏好仍保留原位置，待明确扩展共享数据后设计迁移。

## 尚待后续接入的信息

这些信息不影响当前正式工程的本地功能开发，无需现在逐项确认。

1. Apple Developer Team、CloudKit 容器授权、App Store Connect App 记录。
2. 独立内购 SKU 与价格；首发实际销售组合需对照现有运营配置。
3. 独立远程配置与资源托管地址、客服入口、隐私和条款页面。
4. 广告账户与广告位、统计服务商。

“功能一致”以用户可执行的操作及数据结果为准，不要求保留旧实现缺陷、语言限制、无入口代码或旧 SDK。

# 新用户启动流程对齐

参照 PunchCard 的 `LaunchViewController`、`PrivacyPopUpViewController`、`AppStartup` 和 `SceneLaunchCoordinator`，KeepUp 的本地流程为：

1. 没有隐私同意记录且没有资料时，显示原版启动背景和底部同意面板；点击空白区域不能跳过。
2. 点击“同意并继续”后立即保存独立同意标记，进入不可取消的资料填写流程。未同意时重启仍显示隐私页；同意后中断填写，重启继续填写。
3. 资料确认保存成功时，在一个事务中保存用户资料和三张默认常驻卡。保存失败不进入会员引导。
4. 非会员且存在会员配置时显示新用户会员引导；关闭后才进入可请求运动权限的首页。已有会员跳过该引导。
5. 首页实际出现、会员引导关闭、App 处于前台时，未决定的运动权限才发起请求。启动和停止操作不创建计步器。
6. 已有资料的用户按原版兼容路径跳过隐私和资料引导，不重新添加已移除的默认卡。

本次用户确认继续后置 iCloud 检查与恢复、广告和追踪 SDK；不接入原包云容器或发送新用户通知。协议链接按用户要求暂不接入，隐私页说明为静态文字。启动页使用与桌面 AppIcon 一致的 KeepUp 图标，产品名称显示 KeepUp；支持英文和简体中文。

回归覆盖中英文隐私页、同意前重启、同意后资料未完成重启、资料确认到会员引导再到首页、三张默认卡和完成注册后重启，以及资料校验失败、默认卡删除后编辑资料不恢复。

当前保留的差异：KeepUp 的资料页仍是 RootView 的条件分支，资料保存后才创建首页，再在首页上展示会员引导；原包在隐私同意后先创建首页，资料页和会员引导依次覆盖其上。页面层级还原尚未实施。业务回归共 161 项通过（含后台计步回调崩溃回归），启动专项 UI 回归 3 条通过；真机权限弹窗及修复后的授权回调仍待复测。
